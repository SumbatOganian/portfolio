# 01. Цель, аудитория и контентные границы

## Зачем нужен сайт

Это личное **developer portfolio** для передачи в карьерный центр IT-академии и далее рекрутерам/работодателям. Целевая позиция: Python Backend Junior / Intern. Дополнительное достоинство — навыки frontend и визуального исполнения. Сайт **не продаёт разработку свадебных приглашений** как отдельную услугу, не превращается в рекламный лендинг студии.

Считываемая за 3–5 секунд информация:
- «Python / Django Developer»;
- «ИДЕИ. КОД. РЕЗУЛЬТАТ.»;
- кнопка «Смотреть проекты»;
- GitHub: `https://github.com/SumbatOganian`.

## Главные ограничения контента

- На карточке проекта — **только превью-изображение, название и стрелка**; можно индекс 01/05. Без текста и бейджей.
- При клике — **сразу на настоящий внешний URL**, `target="_blank" rel="noopener noreferrer"`. Не обязательная промежуточная страница кейса.
- Отдельные разделы «Обо мне», «Мой процесс», «Готов к новым проектам» — исключить.
- Навыки представлены минимальными парящими логотипами, а не диаграммой оценки своих способностей.
- В конце компактная связь: GitHub + подтверждённые контактные способы и резюме (если пользователь их предоставил). Не выдумывать контакты.
- Реальные изображения предпочтительнее фотографии ноутбуков в mockup — показывать **сами сайты**. Никакой фальсификации портфолио.
- Наличие исходного кода / работы с AI не доказывает самостоятельное освоение технологии. Не писать «эксперт», «5 лет опыта» и «полностью написал всё самостоятельно» без подтверждений.

## Опыт пользователя

Цель — впечатлить художественным исполнением **и** облегчить просмотр конкретных рабочих продуктов. У любого пользователя всегда есть простой путь из Hero к карточкам и реальным сайтам, в том числе при выключенных анимациях.
