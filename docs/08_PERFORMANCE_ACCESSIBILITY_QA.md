# 08. Производительность, доступность, тестирование

## Performance budgets (ориентир, не жертвовать качеством работы)

- Сначала корректный рендер и функциональность; потом оптимизация. Стремиться к LCP <2.5с, CLS <0.1, INP <200мс на репрезентативных устройствах/сети; это **цели**, не обещанные результаты.
- Рабочий GLB не должен быть десятки мегабайт; target приблизительно 0.5–2.5MB для сцены после оптимизации (только если качество позволяет). KTX2/Draco/Meshopt применять при реальной пользе.
- DPR: адаптивно 1–1.75 desktop, мобильный ограничить 1–1.5, отключать тяжёлый bloom на слабых GPU.
- Использовать один Canvas, reuse материалы и geometry, избегать создания объектов в `useFrame`.
- Скриншоты WebP/AVIF оптимизированные; lazy preload только ближайших карточек; никаких видео фоном без необходимости.
- `prefers-reduced-motion: reduce`: отключить pinned scroll и пролет объектов, статическая hero-подача + обычные clickable карточки и навыки.
- WebGL fallback при контекстной потере, без blank screen.

## Accessibility

- Все карточки — настоящие `<a>` с доступным именем `Открыть сайт InviteCraft` и т.д.
- Контраст текста не ниже WCAG AA для важных элементов; не делать серый микротекст нечитаемым.
- Видимый focus ring, клавиатура может открыть все 5 проектов и навигацию независимо от положения камеры.
- Для фокусированного вне-view карточного элемента прокрутить нужное состояние в видимую область (или использовать доступный DOM fallback).
- Не перехватывать колесо/тач так, что можно застрять; native browser back/forward/history живые.
- `<canvas aria-hidden="true">`; вся смысловая информация дублируется DOM.
- При выключенном JS страница показывает название, 5 ссылок на проекты, GitHub (progressive enhancement желательно).
- Тач-элементы не меньше ~44×44 CSS px.

## QA acceptance checklist

- [ ] В Hero именно холодная зеркальная скульптура справа и крупный заголовок слева, как в утверждённом референсе.
- [ ] Desktop скролл создает **реальное чувство глубины**, карточки выходят **из-за** скульптуры, не появляются сразу в обычной сетке.
- [ ] 5 карточек компактные, каждый реальный screenshot и название без описаний.
- [ ] Все 5 ссылок открываются и возвращение к портфолио не теряет состояние.
- [ ] Mobile по одной карточке ~один экран; при скролле следующая **накрывает**, предыдущая уменьшается и уходит в глубину.
- [ ] Навигация «Проекты», «Навыки», GitHub работает на desktop/mobile.
- [ ] Иконки Python/Django/JavaScript/HTML-CSS/Git парят, не перекрывают другие элементы.
- [ ] Контакты только реальные. Никаких fake numbers, адресов и резюме.
- [ ] iOS Safari, Chrome Android, Desktop Chromium; 320, 375, 390, 768, 1024, 1440, 1920 px.
- [ ] Reduced motion и WebGL-off дают целиком доступную страницу.
- [ ] Resize/rotate/return-to-tab не ломают timeline/Canvas.
- [ ] Нет горизонтального скролла, больших cumulative layout shifts и необоснованных дорогих фильтров.
- [ ] Нет Car, отдельных свадебных шаблонов, «Обо мне», «Мой процесс», «Готов к новым проектам».

## Delivery

Приложить к отчёту Codex: `npm install && npm run dev` / `npm run build` результаты; снимки desktop hero/projects/skills, mobile hero/stack mid-transition/skills; короткие видео desktop scroll и mobile stack; список пройденных проверок и реальных препятствий.
